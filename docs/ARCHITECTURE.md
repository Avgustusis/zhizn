# Архитектура

## Принцип

Правила, данные и интерфейс разделены.

| Часть | Где | Что делает |
|---|---|---|
| Данные | `src/data/` | Все карты с явными эффектами и условиями. Оригинальный текст хранится рядом (`src`), чтобы разбор можно было сверить |
| Движок | `src/engine/` | Чистый TypeScript без интерфейса. Хранит состояние партии и на каждом шаге говорит, какое решение нужно и от кого |
| ИИ | `src/engine/ai/` | Отвечает на те же вопросы, что и человек. Логика — из `reference/engine/sim3.py` |
| Интерфейс | `src/ui/` | Показывает состояние и передаёт решения игрока движку |

## Как движок ведёт партию

Движок — машина состояний. Он не ждёт ввода сам, а останавливается и возвращает **запрос решения**:

```ts
type Pending =
  | { kind: 'choose'; player: number; card: string; options: string[] }   // «А или Б»
  | { kind: 'trump'; player: number; check: CheckInfo }                     // сыграть ли козырь
  | { kind: 'market'; player: number; offers: Offer[] }                     // обмен после хода
  | { kind: 'fork'; player: number; fork: string; paths: string[] }         // развилка
  | ...

engine.state            // всё, что видно на столе
engine.pending          // что нужно решить сейчас (или null — можно ходить дальше)
engine.answer(choice)   // ответ человека или ИИ
```

Из этого следует:

- **Одно устройство, «передай телефон».** Интерфейс показывает запрос тому игроку, чей он.
- **ИИ-соперники** отвечают на те же запросы.
- **Симуляции баланса** запускают движок в Node без интерфейса: тысячи партий ИИ против ИИ.
- **Сетевая игра** потом: движок переезжает на сервер, запросы ходят по сети.
- **Сохранение партии:** состояние и генератор случайных чисел сериализуются в JSON.

Случайность идёт через генератор с зерном (seed), поэтому любую партию можно воспроизвести, а ошибку — повторить.

## Сверка с Python-симуляцией

`reference/engine/sim3.py` — образец. После этапа 4 прогоняем 600 партий ИИ против ИИ на новом движке
и сравниваем средние (счастье, продолжительность жизни, тюрьма, психбольница, классы, эпохи)
с отчётом 10-го прогона (`reference/docs/report.md`). Расхождения либо объясняются новыми системами,
которых не было в симуляции, либо это ошибки переноса.
