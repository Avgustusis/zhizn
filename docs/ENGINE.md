# Движок: проект

Проект ядра (этап 2). Что уже написано, а что ждёт этапа 3 — в таблице в конце.

## 1. Три слоя

| Слой | Где | Правило |
|---|---|---|
| Содержание | `src/data/` | Карты, предметы, смыслы, поле, таблицы чисел, позже здания, знакомства и точки обмена. Движок получает всё это одним объектом `Content` и не знает, сколько там чего |
| Движок | `src/engine/` | Чистый TypeScript: ни React, ни браузера. Работает и на телефоне, и в Node (симуляции) |
| Интерфейс и ИИ | `src/ui/`, `src/engine/ai/` | Отвечают на вопросы движка. Человек и ИИ для движка неразличимы |

## 2. Как движок разговаривает

Движок ведёт партию сам и останавливается только там, где нужно решение. Вопрос всегда одного вида — «выбери один вариант»:

```ts
engine.state          // всё, что лежит на столе (обычные данные, без функций)
engine.pending        // вопрос: { player, type, text, options: [{ id, label, off? }] } или null
engine.answer(id)     // ответ; движок идёт дальше до следующего вопроса
engine.save()         // сохранение
```

Один вид вопроса закрывает всё: выбор на карте, путь на развилке, сыграть ли козырь, что сбросить из ячеек, какое действие рынка взять. Ставка в казино — варианты «1», «2», «3»… Интерфейсу нужен один экран с кнопками, ИИ — одна функция.

Кубики бросает движок. Генератор случайных чисел — с зерном, его состояние лежит в `state`: одна и та же партия с теми же ответами повторяется точно. Так воспроизводятся ошибки и сверяются симуляции.

Всё, что произошло, движок пишет в журнал событий (`state.log`): бросок, карта, проверка с кубиками и поправками, изменение числа, предмет. Интерфейс показывает журнал игроку; тесты проверяют по нему правила.

## 3. Как устроен код правил

Правила написаны обычными функциями-генераторами: там, где нужен ответ игрока, функция делает `yield` вопроса и получает ответ. Правило читается как текст книги правил, без ручных автоматов состояний:

```ts
function* playCard(g, p, card) {
  if (!cond(g, p, card.requires)) return 'не подошла'
  if (yield* cancelByTrump(g, p, card)) return 'отменена'
  yield* run(g, p, card.effect, ctx)
}
```

Генератор нельзя сохранить в файл, поэтому партия режется на **шаги**: ход игрока, мировой ход, подготовка. Между шагами всё состояние лежит в `state`. Сохранение = снимок `state` на начало шага + ответы, данные внутри шага; при загрузке шаг проигрывается заново с теми же ответами. Отсюда же отмена последнего ответа, перенос на сервер для сетевой игры (сервер хранит только сохранение) и точный повтор ошибки по файлу сохранения.

## 4. Ход игрока

```
начало хода ──► вопрос «ход»: бросить кубик (с Молодости ещё «эмиграция вместо движения»)
движение     ──► по клеткам; напечатанная развилка — шлагбаум; вход в отрезок и «Итог воспитания» — на проходе
клетка       ──► карта колоды клетки (в институте — карта института); не подошла — под низ, следующая
карта        ──► условие → отмена козырем → шаги эффекта → правила после карты (#закон и тюрьма)
слоты        ──► ■ основное · ▲ дополнительное · ◆ рынок молодости (только Молодость)
конец хода   ──► траты, пенсия, старение; кабала; смерть; пересчёт счастья
```

**Слоты.** После события у игрока есть ■ и ▲, в Молодости ещё ◆. Каждое действие — запись в данных со своей ценой в слотах: Работа ■, малый обмен ▲, знакомство ▲, большой обмен ■+▲, решение рынка молодости ◆. Движок спрашивает «что делаешь?», пока слоты не кончились или игрок не закончил ход. Новое действие — новая запись в данных, код не меняется.

**Город.** Здание — запись в данных: кольцо (окраина, середина, центр), своя колода знакомств, свои точки обмена. Доступ считает одна функция по таблице: позиция страны проживания и класс (Олигархи — везде, Мафия — на кольцо глубже). Знакомство — действие ▲: карта из колоды здания, тот же формат и тот же исполнитель, что у событий.

**Колоды** — просто именованные стопки id карт. Колода знакомств здания, стопка класса, «Верхи» — всё одно и то же устройство.

## 5. Исполнитель карт

Исполнитель обходит дерево шагов карты (`effect`). На каждую карту заводится контекст:

| В контексте | Зачем |
|---|---|
| Бросок d6 уровня | Параллельные `d6` читают один бросок; `d6` внутри исхода другого `d6` — новый уровень и новый бросок |
| Теги карты | По ним проверки получают поправки культуры, характера, предметов, класса, идеологии |
| Характеристика последней проверки | Для «успех — +1 к ней» |
| Выбранные варианты | Для условия «выбрал такой-то вариант» |
| Источник | Событие, институт, рынок: возрастной сдвиг — только у карт; «рынок не убивает» — только у обменов |
| Сила полюса | В колоде «по полюсам» числа веток полюса при «сильно» на 1 крупнее |

**Изменение числа** проходит одну трубу: число с карты → «сильно» в колоде культуры → возрастной сдвиг (только физ. и псих., только карты) → потолки (характеристики 10, с чудом 12; здоровье +10; Возможности +15 или +20) → пороги (здоровье −10, Возможности −15).

**Проверка**: 3d6 + характеристика ≥ сложность.

1. Характеристику из нескольких движок берёт ту, с которой шанс выше (при равенстве — первую по карте). Если карта даёт «+1 к ней», спрашивает игрока.
2. Поправки карты (`mods`): новая сложность, ±к броску, преимущество, помеха, автоуспех.
3. Ситуативные поправки по тегам — культура, характер, предметы, класс, идеология, мода, временные поправки. Считаются все полностью и срезаются до ±3.
4. Преимущество и помеха: несколько источников — всё равно одно; друг друга гасят.
5. Козырь: если подходящий есть, игрок решает до броска. Козырь идёт сверх потолка ±3.

## 6. Здоровье, смерть, смысл

- **−10 физ.** — смерть (в кабале и от рынка — стоп на −9).
- **−10 псих.**: Детство — −9 и пропуск хода; Юность — первый раз срыв, второй — отделение на 6 ходов; дальше d6 по позиции страны: психбольница или смерть.
- **Вход в Древность** — 3d6 + физ. ≥ 12 с поправками; провал — смерть в конце Старости.
- **Смысл**: бросок 3d6 при рождении и на входе в Юность, Молодость, Зрелость; Династия и отказ от неё; кризис среднего возраста; Серость.
- **Счастье** пересчитывается после каждой карты и действия. Условия «соб.» движок отслеживает с рождения по всем картам смысла сразу — поэтому карта, вытянутая в Зрелости, сразу засчитывает прошлое.

## 7. Состояние

`GameState` — обычные данные: настройки партии, генератор, часы мира, пять стран с отношениями, профили семи культур, стопки колод, игроки, журнал. У игрока: пол, раса, культура, страна и гражданство, три шкалы семьи, класс, здоровье, характеристики, характер, место на поле, предметы, институт, смысл, журнал жизни (счётчики и отметки), временные поправки, отложенные эффекты.

## 9. Как прочитаны спорные места

Там, где концепция оставляет выбор, движок делает так. Каждая строка — одно место в коде или одно число в `src/data/tables.ts`; поправить легко.

| Место | Что делает движок | Откуда |
|---|---|---|
| Козырь на проверку | Игрок решает **до** броска, видя шанс | Концепция: «+5 к одной проверке»; порядок не назван |
| Несколько характеристик на выбор | Движок берёт ту, с которой шанс выше; спрашивает только там, где карта даёт «+1 к ней» | Меньше вопросов игроку |
| Ячеек козырей нет (финансы и положение ниже +1) | Козырь взять некуда: карта не приходит | «Ниже +1 — нет» |
| Ячейки заняты | Вопрос: что сбросить (с ценой сброса) или не брать новое | «Сброс предметов» |
| Стигма или статус с тем же именем | Второй раз не кладётся | «Стигма одна» |
| «Итог воспитания» | Срабатывает на проходе клетки; очки делятся по очереди между двумя характеристиками класса семьи | Ребёнок своей жизнью не управляет |
| В институте | Фишка идёт по d6, как обычно; развилки и клетки проходят мимо; вход в отрезок срабатывает | Памятка 6. В Python-симуляции фишка шла по одной клетке |
| Подростковое отделение | Стигмы «Учёт» не оставляет | Концепция говорит об «Учёте» у взрослых |
| Отказ от Династии | Решение при рождении и на каждом входе, пока идёт отказ. «Прекратить» — навсегда. Бросок в Зрелости — последний, неудача — «Серость» | «Путь династии» |
| Кризис среднего возраста | Новая карта вслепую; после смены карта закреплена | «Обычный путь», п. 4 |
| Одобрение смысла культурой | ±1 псих. один раз за каждое условие — когда оно выполнилось впервые; за уже выполненное при получении карты — ничего | «При каждом выполненном условии» |
| «Супруг(а) уходит» | Развод, если на карте нет тега #утрата; с #утрата — вдовство, в счёт разводов не идёт | Формат не различает |
| Меньшинства страны | 0–3, каждое — раса или культура (монеткой); в мультикультурной стране основных рас и культур по 2–3 | Карта страны в макетах; числа не названы |
| Раса и культура при рождении | Основная раса и основная культура — независимо; меньшинство меняет что-то одно | Памятка 5 |
| Партнёр | Класс: 60% свой, иначе по весам населения; культура 80% своя; раса 85% своя | Числа из Python-симуляции |
| Мода | Перебрасывается для страны игрока, когда он входит в отрезок | «На каждом новом отрезке жизни» |
| Сыгранная карта | Уходит под низ своей колоды; «замешать» — в случайное место | Памятка 6 |
